# ADR-002: Role-Based Access on Backend Routes

## Context
Certain endpoints (payments listing, course mutations) must be restricted to admins.

## Decision
Apply auth middleware across APIs; add `requireAdmin` guard for sensitive routes (e.g., /api/payments, course CRUD in enrollments meta routes).

## Alternatives
- Per-route inline auth checks without shared middleware
- External API gateway enforcing auth before Express
- Session-based auth without JWT tokens

## Rationale
Central middleware keeps enforcement consistent with minimal code for a solo project; JWT tokens already issued/validated in the existing stack; role checks gate finance-sensitive endpoints.

## Consequences
- Pros: Simple enforcement, minimal code.
- Cons: Middleware must stay in sync with new routes; relies on correct role claims in tokens/sessions.
