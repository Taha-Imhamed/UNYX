# ADR-003: Seed Data with Ledger Normalization (Deprecated)

## Context
Initial iterations relied on seeded demo data to showcase dashboards and finance flows. Production readiness now requires running purely against live Supabase/Postgres data with no seeded fallbacks.

## Decision
Seeding has been removed from application startup. Environments must be provisioned with real data via migrations or administrative tooling instead of bundled fixtures.

## Alternatives
- Maintain optional seed scripts for testing (rejected for production parity).
- Keep legacy demo data in code (rejected to avoid stale copies).

## Consequences
- Pros: No mock/demo data in runtime; production parity across environments; clearer failure modes when data is missing.
- Cons: Test environments need their own data provisioning; dashboards may render empty states until data is loaded.
